## 🤖 IA na prática

Kubernetes tem uma curva de aprendizado íngreme — YAML denso, muitos objetos inter-relacionados (Pod, Service, Ingress, ConfigMap) e comandos `kubectl` com dezenas de flags. É exatamente o tipo de complexidade onde assistentes de IA ajudam bastante, tanto para aprender quanto para operar clusters reais no dia a dia.

**Para aprender**
- Cole um manifesto YAML de um Deployment ou Service e peça: *"explique campo por campo o que cada linha faz e por que ela está aí"* — o formato do Kubernetes é verboso e a IA já viu milhares de exemplos parecidos.
- Cole um erro real de `kubectl describe pod` (ex.: `CrashLoopBackOff`, `ImagePullBackOff`) e peça: *"quais as causas mais prováveis e como investigar cada uma"*.
- Peça exercícios práticos: *"me dê um desafio de Kubernetes envolvendo ConfigMap e Secret juntos, sem me dar a resposta"* — você tenta no [killercoda](https://killercoda.com/kubernetes), a IA revisa.
- Use um assistente de terminal como o [k8sgpt](https://k8sgpt.ai/) para escanear o cluster e receber, em linguagem natural, o diagnóstico de recursos com problema.

**Para trabalhar**
- Ferramentas como [GitHub Copilot](https://github.com/features/copilot) e [Claude Code](https://code.claude.com/docs/en/overview) ajudam a escrever manifestos YAML, Helm charts e pipelines de CI/CD a partir de uma descrição em linguagem natural — sempre revise antes de aplicar em produção.
- O [kubectl-ai](https://github.com/GoogleCloudPlatform/kubectl-ai) é um plugin que traduz comandos em linguagem natural para `kubectl`, útil para explorar um cluster desconhecido.
- O [k8sgpt](https://k8sgpt.ai/) analisa o estado do cluster (pods travados, eventos de erro, configurações inconsistentes) e sugere causas e correções.
- Depois de aceitar qualquer manifesto sugerido por IA, valide com o [kubeval](https://github.com/instrumenta/kubeval) e rode um scanner de segurança como o [Trivy](https://github.com/aquasecurity/trivy) antes de aplicar no cluster.

**Limites e boas práticas**
- IA **inventa flags, campos de API e nomes de recursos** com frequência, principalmente para versões recentes da API do Kubernetes. Confira sempre na [referência oficial do kubectl](https://kubernetes.io/docs/reference/generated/kubectl/kubectl-commands).
- Nunca peça para uma IA gerar um manifesto com senhas, tokens ou chaves de API embutidas em `env:` — use `Secret` do Kubernetes ou um cofre externo (Vault, cloud KMS).
- Desconfie de um manifesto sugerido que rode containers como `root`, sem `resources.limits` definidos, ou aplique `RoleBinding` amplo demais (ex.: `cluster-admin` para uma aplicação comum).
- Antes de rodar `kubectl apply` gerado por IA direto em produção, teste primeiro com `kubectl apply --dry-run=server` ou em um cluster local (Minikube/kind).
